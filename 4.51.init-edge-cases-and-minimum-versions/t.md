# `init` edge cases and minimum versions

`load_history_config` always says `refs/tasks/main on origin is not a yman history`, even on the repair path or with a local-only history, including a conflicted or hand-broken local `config.toml`. A fresh `init` whose push fails for a reason other than rejection bails before `--hooks` and the summary, although the tracker already exists locally. `init --offline` in a clone whose origin already has tasks creates an unrelated root and the next sync gets the re-init error, which `docs/setup.md` §2 does not warn about. The merge driver is registered as `"<exe>" merge-driver %O %A %B`, which breaks under sh when the path contains `"`, `$`, a backtick or a UNC `\\`. `discover` relies on `--path-format=absolute`, which git before 2.31 echoes back as a path, and the fallback uses the same flag; `README.md` says git 2.42 or newer but nothing checks it, and `Cargo.toml` has no `rust-version` although edition 2024 needs 1.85.

- Where: `src/commands/init.rs` (`load_history_config`, `run`, `register_merge_driver`), `src/repo.rs` (`discover`, `discover_separately`), `docs/setup.md` §2, `README.md` requirements, `Cargo.toml`.
- Done when: the error names the actual source, a failed push still installs hooks and prints the summary with a warning, `--offline` on a populated origin is documented or refused, the driver path is single-quoted, `rust-version` is set, and the git minimum is either checked at runtime or stated as enforced by CI.
