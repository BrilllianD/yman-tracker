# documentation drift found by the audit

A bundle of small disagreements between the docs, the help text and the code. In `docs/commands.md` §2 a paragraph sits between the rows of the commit-subject table, so the four `sync` rows render as plain text. `docs/commands.md` §3 `status --json` omits the `autosync` key the code emits. `docs/storage.md` §3 says "exactly these" but its table and the §4 config comment omit `yman.autosync`. `docs/errors.md` lacks `git worktree add failed`. `skills/yman/SKILL.md` and `docs/agents.md` say `--json` exists on `ls`, `show`, `status` and `tags` only, but `plan --json` exists (the guide is capped at 72 lines by a test, so reword rather than add), and "JSON omits nothing" ignores that `ls` and `plan` drop `body` without `-l`. The help for `edit`, `add -e` and `comment -e` says `$EDITOR` while `resolve_editor` checks `$VISUAL` first. The top-level `after_help` body line omits `add -m` and `set --body-file`. `CHANGELOG.md` has a stray blank line splitting the 0.5.0 "Added" list. `CLAUDE.md` says 104 unit and 124 integration tests; there are 111 and 132. `docs/SUMMARY.md` links `README.md`, `skill.md` and `CHANGELOG.md`, which do not exist under `docs/`, so they break on GitHub. `scripts/book.sh` does not check that every `docs/*.md` is listed in `SUMMARY.md` as `README.md` promises, and uses the anchor fragment as an unescaped regex.

- Where: `docs/commands.md`, `docs/storage.md`, `docs/errors.md`, `docs/agents.md`, `skills/yman/SKILL.md`, `src/cli.rs` (help strings), `CHANGELOG.md`, `CLAUDE.md`, `docs/SUMMARY.md`, `scripts/book.sh`.
- Done when: each item is corrected, `yman guide` still fits its line cap, and `sh scripts/book.sh` is green.
